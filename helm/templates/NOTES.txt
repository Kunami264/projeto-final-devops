ANTES DA PRIMEIRA INSTALAÇÃO NESTE NAMESPACE, se ainda não existir, cria o
Secret de acesso ao GHCR (nunca gerido por este chart):

  kubectl create secret docker-registry {{ .Values.image.pullSecretName }} \
    --docker-server=ghcr.io \
    --docker-username=<o-teu-utilizador-github> \
    --docker-password=<personal-access-token-com-scope-read:packages> \
    --docker-email=<o-teu-email> \
    -n {{ .Release.Namespace }}

Estado dos workloads:
  kubectl get pods -n {{ .Release.Namespace }}

service-orders está exposto através de Ingress:

  https://{{ .Values.ingress.host }}/health

{{- else if eq .Values.serviceOrders.service.type "NodePort" }}

service-orders está exposto externamente via NodePort:
  http://<IP-de-um-nó-do-cluster>:{{ .Values.serviceOrders.service.nodePort }}/health
{{- else }}

service-orders e service-users não têm exposição externa neste ambiente
(ambos ClusterIP). Para consulta local:
  kubectl port-forward -n {{ .Release.Namespace }} svc/service-orders 8001:8001
{{- end }}

Para consultar a UI do Jaeger (assumindo o namespace observability já aplicado):
  kubectl port-forward -n observability svc/jaeger 16686:16686

Para consultar o Prometheus (idem, ver `make k8s-observability-apply`):
  kubectl port-forward -n observability svc/prometheus 9090:9090

Todos os endpoints de negócio (/users, /orders) exigem Bearer JWT — gera um
token de teste com:
  make token SUBJECT=daniel SCOPE="orders:read orders:write users:read"
